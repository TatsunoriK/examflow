# ExamFlow

ระบบสอบออนไลน์ภาษาไทย มีหน้าฝั่งอาจารย์และนักเรียน

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป และ npm

1. เปิดโฟลเดอร์นี้และติดตั้งด้วย `npm install`
2. สร้างแอปด้วย `npm run build` แล้วสร้างฐานข้อมูลทดสอบด้วย `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_yellow_molly_hayes.sql`
   จากนั้นใช้คำสั่งเดิมซ้ำโดยเปลี่ยนไฟล์เป็น `drizzle/0001_handy_taskmaster.sql` และ `drizzle/0002_camera_proctoring.sql` ตามลำดับ
3. เปิดเว็บด้วย `npm run dev` แล้วเปิด URL ที่แสดง
4. หน้าทดสอบในเครื่องใช้ตัวตนจำลองของ starter; การเผยแพร่จริงใช้ตัวตนจาก Sites และตรวจสิทธิ์ทุก endpoint

## การใช้งาน

- อาจารย์: สร้างข้อสอบแบบปรนัย 4 ตัวเลือก เลือกเฉลย กำหนดเวลา แล้วส่งรหัสให้นักเรียน
- นักเรียน: เข้าบัญชีของตน กรอกรหัสและชื่อ ยินยอมการบันทึก แล้วอนุญาตเว็บแคมและเลือก Entire screen
- หยุดแชร์: ระบบพักการตอบ แต่เวลาสอบยังเดิน
- สลับแท็บ/เสียโฟกัส: แจ้งเตือนและเก็บเหตุการณ์ให้อาจารย์ตรวจ
- วิดีโอหน้าจอและเว็บแคมถูกอัปโหลดเป็นช่วงไปยัง R2 อาจารย์เจ้าของข้อสอบเท่านั้นที่เรียกดูได้ เว็บแคมเก็บใต้ prefix `camera/`
- เมื่อเชื่อม Python inference service แล้ว ระบบวิเคราะห์คลิปเว็บแคมและแสดงสัญญาณให้ครูตรวจในหน้าผลสอบ หากไม่มีโมเดลหรือบริการ ผลจะแสดงว่าไม่พร้อมใช้งาน ไม่สร้างผล AI ขึ้นแทน
- ส่งคำตอบและตรวจคะแนนบนเซิร์ฟเวอร์ ไม่ส่งเฉลยให้เครื่องนักเรียน

## ข้อจำกัด

เบราว์เซอร์ต้องได้รับความยินยอมจากผู้ใช้ ไม่สามารถเริ่มบันทึกโดยลับ สัญญาณจากโมเดลไม่ใช่หลักฐานยืนยันการทุจริตและห้ามใช้ลงโทษโดยอัตโนมัติ คุณภาพโมเดลขึ้นกับ label ที่คนตรวจและการทดสอบกับข้อมูลจริง ไม่สามารถบังคับนักเรียนที่ดัดแปลง client หรือเรียก API เองให้บันทึกวิดีโอจริงได้

ทดสอบบน Chrome / Edge บนคอมพิวเตอร์ผ่าน HTTPS หรือ localhost ก่อนใช้สอบจริง หากปิดแท็บหรืออินเทอร์เน็ตขาด วิดีโอช่วงที่ยังไม่อัปโหลดอาจสูญหาย เมื่อกลับมาเข้าด้วยรหัสเดิมจะใช้เวลาสอบเดิมและคำตอบที่บันทึกบนเซิร์ฟเวอร์แล้ว ผู้ใช้ที่ลงชื่อเข้าใช้สามารถสร้างข้อสอบของตัวเองได้ การเลือกฝั่งอาจารย์เป็นการเลือกหน้าทำงาน ไม่ใช่การยืนยันตำแหน่งอาจารย์โดยสถาบัน

## การเผยแพร่

`.openai/hosting.json` กำหนด D1 เป็น DB และ R2 เป็น BUCKET ใช้ Sites workflow สำหรับ build และ deployment เว็บที่ลงทะเบียนไว้ยังเป็นส่วนตัว เจ้าของต้องตั้งสิทธิ์ให้ผู้เข้าสอบก่อนใช้งานหลายบัญชี การสร้างเว็บครั้งนี้ยังไม่ยืนยันว่าเผยแพร่สำเร็จ

ก่อนใช้เว็บแคมจริง ผู้ดูแลต้องตั้ง R2 lifecycle rule ให้ลบ object ใต้ `camera/` หลัง 30 วัน (การเปลี่ยนโค้ดไม่ได้ตั้ง lifecycle ให้ bucket) และกำหนดนโยบายลบข้อมูลผลวิเคราะห์ใน D1 กับสถาบัน

## เชื่อมต่อโมเดลเว็บแคม

โมเดลทำงานใน Python service แยกจาก Cloudflare Worker และต้องผ่านการฝึกด้วย label จากผู้ตรวจจริงก่อน ดูขั้นตอนเตรียม artifact, deploy container, ตั้ง secret และ retention ที่ [proctoring_service/README.md](proctoring_service/README.md) ตั้ง `PROCTORING_API_URL` และ Worker secret `PROCTORING_API_TOKEN` ก่อนใช้; หากยังไม่ตั้งค่า ระบบจะเก็บวิดีโอและรายงานสถานะว่าโมเดลยังไม่เชื่อมต่อ

## การทดสอบ

ใช้ `npm run test:api` เพื่อตรวจ API ด้วยฐานข้อมูล SQLite ในหน่วยความจำและพื้นที่วิดีโอจำลอง การทดสอบนี้ไม่ทดแทนการทดสอบแชร์หน้าจอจริงบนเบราว์เซอร์

## เปิดดูบนเครื่องแบบพร้อมฐานข้อมูลทดสอบ

ดูขั้นตอนใน [portable/README.md](portable/README.md) ใช้ Node.js 24 ขึ้นไป แล้วรัน `npm install`, `npm run build`, `npm start` จากโฟลเดอร์ `portable` เว็บจะเปิดที่ http://127.0.0.1:4173/ โดยใช้บัญชีทดลองและฐานข้อมูลบนเครื่อง ไม่ใช่เว็บที่เผยแพร่ออนไลน์
